# UX Strategy

## Problem Statement
- **신부는** 원하는 부케를 말과 사진으로 전하기 어렵고, 받기 전엔 나와 어울리는지 확인할 수 없다.
  → 원하는 걸 보여주고, 받기 전에 내 모습으로 미리 확인하고 싶다.
- **플로리스트는** 레퍼런스와 손그림으로 요구를 알아듣고, 확정한 내용도 카톡으로 다시 확인한다.
  → 요구를 한 번에 이해하고, 확정한 건 다시 묻지 않고 싶다.

**문제는 꽃이 아니라, 원하는 걸 전하고 · 바뀐 걸 알리고 · 확정한 걸 남기는 과정이다.**

## Core Experience
손님이 이번 주 꽃으로 만든 **3D 시안 한 장이 요청부터 결과까지의 기준**이 된다.

UX 원칙의 근거: **Recognition over Recall** — 사람은 원하는 걸 떠올려 설명하기보다 눈앞에 보이는 걸 알아보는 데 훨씬 능하다.

## UX Principles
1. **레퍼런스에서 출발해요** — 사진을 버리게 하지 않고, 원하는 부분만 고르고 바꾸게 한다
2. **정확히보다 범위를 맞춰요** — 똑같은 재현 대신, 내 모습에서 어울리는 범위와 바뀔 수 있는 꽃을 미리 보여준다
3. **확정은 기록으로 남겨요** — 확정한 시안·가격·기한이 한곳에 남아 다시 묻지 않는다

## MVP Scope
7개 아이디어를 Impact · Confidence · Effort로 평가. **"전하기"와 "남기기"부터** 만든다.

| 포함 (MVP) | 제외 (Phase 2 / Later) |
|---|---|
| 3D 조합 시안 (H1) | 대체 꽃 범위 합의 — 꽃 데이터가 먼저 필요 |
| 사이즈별 가격 범위 (H2, 가볍게) | AI 레퍼런스 자동 분석 — MVP는 사진 첨부 + 색감 고르기로 대체 |
| 시안 이미지 저장·전송 = 확정 기록 (H3) | 드레스 합성 (H4) — 부케 변형 문제로 기술 준비 후 |
| | 배송 전 사진 승인 |

> 참고: 최종 디자인(구현 페이지)에는 II. DRESS 탭과 조명이 포함돼 있다. 프로토타입에서는 **샘플 드레스·조명 전환 수준**으로 H4를 프로토타입 테스트에서 확인한다.

## Feature Priority
| 우선순위 | 기능 | 이유 |
|---|---|---|
| P0 | 3D 캔버스 (회전·시점·HAND) | 핵심 가치 "보고 고른다" |
| P0 | FLOWER 탭: 모양 · 크기 · 색 & 꽃 | 핵심 문제 "전하기" — 색감·분위기 → 사이즈 순으로 작게 시작 |
| P0 | 예상 견적 실시간 계산 | 플로리스트가 가장 많이 받는 문의가 가격 |
| P0 | DOWNLOAD IMAGE / ASK TO FLORIST | 시안 = 주문서, 카톡 왕복 감소 |
| P1 | 레퍼런스 이미지 업로드 | 원칙 01, MVP는 첨부만 |
| P1 | 시안 버전 비교 · Undo/Redo · CLEAR | 안심하고 바꿔볼 수 있게 |
| P2 | DRESS 탭 (샘플 드레스·조명) | H4 검증용 |

## Success Criteria (솔루션 가설과 측정 지표)
| 가설 | 이렇게 하면 → 이렇게 바뀔 것 | 확인할 숫자 |
|---|---|---|
| H1 · 레퍼런스에서 출발 | 레퍼런스에서 원하는 부분만 골라 3D로 조합하면 → 손그림·추가 설명 없이 한 번에 전한다 | 시안 완성까지 걸린 시간, 추가 질문 없이 견적 낸 비율 |
| H2 · 범위를 미리 맞추기 | 구할 수 있는 꽃·대체 후보·가격 범위를 함께 보여주면 → "사진과 다르다" 불만이 준다 | 대체 꽃 관련 카톡 횟수, 받은 뒤 시안 대비 만족도 |
| H3 · 확정은 기록으로 | 확정한 시안·가격·기한을 한 페이지에 남기면 → 확인 카톡과 분쟁이 준다 | 주문 1건당 카톡 왕복 수, 첫 문의부터 확정까지 걸린 날 |
| H4 · 드레스와 함께 보기 | 드레스 위에 3D 부케를 합성해 보면 → 주문 뒤 크기·색 수정이 준다 | 합성 후 크기·색을 바꾼 사람 수, 결정 확신 점수(5점) |
